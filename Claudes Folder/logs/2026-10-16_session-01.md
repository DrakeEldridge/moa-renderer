# Session 01: 2026-10-16 (NZ time)

## Planning (first half of the chat)

The project was planned in conversation. The full plan lives in the design doc
(https://claude.ai/code/artifact/8bf26f6e-14ce-49b0-b4e8-3c5d4d2b9062). Key points:

- Goal: recreate how Redshift felt around 2018: an easy, fast, interactive GPU renderer with
  great shader nodes and free plugins for many hosts. Free, open source, no subscription.
- Started from Drake asking about using REA (an AI reverse-engineering tool) on Redshift and V-Ray.
  Decided against that: licence terms, and it would undermine the independent-build claim.
  Learn from public sources instead (PBRT, Cycles source, OptiX samples, SIGGRAPH courses).
- Host integration through USD Hydra (Houdini Solaris native, Blender 4.0+, Maya via MayaUSD).
  Houdini is the priority host. Unreal: offline cinematics plugin and texture baking, not a
  real-time game renderer.
- AI toolkit: OptiX denoise and 2x upscale; frame generation driven by renderer data (render every
  other frame, rebuild the rest from motion vectors, albedo/lighting split, direct-light
  re-render, world-space GI cache, confidence mask); post motion blur and depth of field
  (vector / sub-frame / true 3D, auto layers or deep data); stylized/comic shading; "describe the
  look" shader builder; photo-match assistant with an "apply suggestions" button and undo; render coach.
- Redshift-inspired feature list (GI engines, volumetric god rays, skin/SSS/glass/metal/mirror/
  water presets, proxies and instancing, tick-box AOVs, shadow catcher, interior mapping, shell
  volumes inspired by Drake's teacher Brian Samuels' thin-shell planet storm sims).
- Modern additions: path guiding (Intel Open PGL), radiance caching (NVIDIA RTXGI SHaRC/NRC),
  Gaussian splats, light mix, click-to-light, debug views.
- Platforms: Windows + NVIDIA first; Linux next (cheap); AMD (HIP) and Mac (Metal) later.
- Licensing: Apache 2.0, milestone-based donations, optional paid extras later.

## Milestone 1 build

Files written: `CMakeLists.txt`, `src/main.cpp`, `src/Renderer.{h,cpp}`, `src/Scene.{h,cpp}`,
`src/ImageIO.{h,cpp}`, `src/CudaBuffer.h`, `src/Check.h`, `src/device/{pathtracer.cu,
LaunchParams.h, vec_math.h, random.h}`, `build.bat`, `run.bat`, README, LICENSE.

Design notes:
- Raygen runs the whole path loop; the radiance closest-hit returns a HitInfo through a pointer
  packed into two payload slots. Shadow rays use TERMINATE_ON_FIRST_HIT | DISABLE_CLOSESTHIT, and
  their miss program sets payload 0 to 1. One hit group serves both ray types.
- Non-indexed triangles; per-triangle material index; flat normals computed in the closest-hit program.
- Glass needs outward normals, so `Scene::addBlock` orients each face away from the block centre.
- Running average per launch (`lerp` with 1/(n+1)); every launch uses the same samples-per-launch count.
- Denoiser uses OPTIX_DENOISER_MODEL_KIND_AOV, which expects **world-space** normals (checked
  in the optix_types.h comments; the older HDR model wanted camera space).
- PTX built by a CMake OBJECT library with CUDA_PTX_COMPILATION, arch 75, copied next to moa.exe
  after the build. Cfgmgr32 linked on Windows (optix_stubs.h uses it to find the driver DLL).

Verification in the cloud workspace (no GPU):
- NVRTC compiled `pathtracer.cu` to PTX (compute_75). Host compiled with g++ -Wall -Wextra,
  no warnings. `sizeof(LaunchParams)` = 208 on host and in PTX.
- CPU mock (`tools/cpu_mock`) ran the real device code: Cornell box correct (red wall left, green
  right, light on the ceiling), normals pass correct, glass refracts, mirror reflects.
- Firefly issue found and fixed (see index: FIX/FAILED clamp entries).
- Not verified yet: the Windows build itself and the OptiX runtime calls (pipeline creation,
  stack sizes, denoiser). These need Drake's first build.
